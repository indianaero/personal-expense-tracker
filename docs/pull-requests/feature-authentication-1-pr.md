## Summary
- Establishes the initial data layer for the app with a reusable database connection utility
- Defines the four core domain models — User, Expense, Category, and MonthlySummary — as Mongoose schemas
- Introduces a shared `types/models.ts` file so TypeScript types are derived from the schemas rather than duplicated

## Changes

**Database connection**
- `lib/db/connect.ts` — MongoDB connection helper with connection caching to avoid redundant connections in serverless functions

**Domain models**
- `models/User.ts` — user schema with email, name, provider, and password hash fields
- `models/Expense.ts` — expense schema with amount, description, date, category reference, and recurrence flag
- `models/Category.ts` — category schema with name, colour, and default/user-owned distinction
- `models/MonthlySummary.ts` — pre-computed monthly rollup schema for dashboard performance

**Shared types**
- `types/models.ts` — TypeScript interfaces inferred from schemas, used across API routes and service functions

## How to test
1. Run `npm run build` — TypeScript should compile cleanly with no type errors on the new model files
2. Confirm `lib/db/connect.ts` exports a `connectToDatabase` function
3. Confirm `types/models.ts` exports `User`, `Expense`, `Category`, and `MonthlySummary` interfaces
4. Import a model in a REPL or test file and verify the schema fields match the spec
